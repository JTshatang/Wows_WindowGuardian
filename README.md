# WindowGuardian

《战舰世界》(World of Warships) 的窗口位置守护工具 —— **单屏、双屏都能用**。

你是否会经常边玩战舰世界边开副屏看视频刷知乎？
为了游戏性能，战舰世界一直开着独占全屏而不是窗口化，这样在进入和退出全屏时，其他屏幕
摆放的窗口就会到处漂移，每次开启游戏全屏前都要重新摆放浏览器窗口，非常烦人。
还有就是游戏想开2K但是显示器是4K的，切换分辨率的过程也会导致窗口乱飞。

以下是原因解释和解决办法：

游戏进出**独占全屏**时会改变屏幕分辨率，Windows 顺势把你的后台窗口挤小、挪位，
而且**恢复后不会自己滚回来**。这个工具只在"游戏正在切换显示模式"的那几秒里动手，
把你的浏览器、聊天、资源管理器按原样放回去；其余时间完全不干预 ——
你手动拖窗口、缩放、用 Win+方向键摆放，它一句话都不说。

---

## 为什么需要它

### 单屏：整个桌面分辨率都在变

游戏要独占全屏就得换分辨率，而**换分辨率 = 整个桌面跟着换**。实测一次进出的完整序列：

```
3840x2160  →  1920x1080  →  2560x1440  →  3840x2160
```

注意它是**分步**走的，不是一步到位 —— 游戏先切到 1920x1080 启动，再切到目标分辨率。

桌面缩到 1920x1080 的一瞬间，任何放不下的窗口都会被 Windows 就地改动
（位置被推进新边界、尺寸被裁小，实测宽度 `3783 → 1860`），而**恢复 4K 时不会归还**。

结果就是：每打一局，你的窗口小一圈、往角落靠一点。单屏下这种位移特别容易被忽略 ——
没有"另一块屏"做参照，你只会以为是系统偶尔抽风。

> 如果你的游戏和桌面用同一分辨率（比如无边框窗口 + 原生分辨率），
> 那就不会发生分辨率切换，这个工具也就什么都不做 —— 这是正常现象，不是坏了。

### 双屏：副屏的窗口被整体推走

Windows 会让**副屏的 X 坐标始终等于主屏当前的宽度**（实测 `3840 → 1920 → 2560 → 3840`），
用它来保持两块屏边缘相邻。主屏一缩，副屏就被拽到新的桌面右边缘，上面的窗口全部跟着平移。

这也是**一次单向钳制 —— 主屏恢复后不会回滚**，于是每次进出全屏都累积位移。

### 它解决的是"所有窗口"，不只是被推走的那些

DeskBox 那类自带 `DisplayAreaWatcher` + `WidgetManager` 的工具不受影响，因为它会主动复位；
本工具把这套自救能力**推广到所有窗口**，不管那个程序自己会不会自救。

## 用法

双击 `WindowGuardian.exe`，弹出控制面板：

```
状态： ● 监视中
基准： 27 个窗口 / DISPLAY1 3840x2160@60 [主]  |  DISPLAY2 2560x1440@165
当前： DISPLAY1 3840x2160@60 [主]  |  DISPLAY2 2560x1440@165
[暂停监视] [以当前布局为基准] [立即还原] [打开日志]
[ ] 开机自启        关闭本窗口 = 收进托盘，程序继续运行
最近事件： <实时日志>
```

**关闭窗口不会退出程序**，只是收进托盘（盾牌图标），守护照常工作。要真正退出用托盘右键菜单。

> 托盘图标默认可能被 Windows 塞进任务栏的「隐藏的图标 `^`」里，找不到就点那个 `^`。

## 工作逻辑

1. 每 200ms 采一次显示器拓扑，算出两个签名：
   - **完整签名**（含工作区 `rcWork`）—— 用于判断"有没有变化"。任务栏在切换期间会反复隐藏/显示，
     工作区在 `6338` 和 `6400` 之间抖动，这些也算需要守护的变化。
   - **几何签名**（只有屏幕矩形 + 分辨率 + 刷新率 + 主副标志，**不含工作区**）—— 用于判断
     "是否已回到基准"。早期版本用完整签名判断，导致任务栏一抖就误判成"还没回基准"，
     **绝对还原永远不执行**，这是曾经失效的一个真实原因。
2. 维护**滚动基准**：窗口矩形只有**连续两个采样周期都没变**才被记入，所以只有你"放下"窗口
   之后的位置才会成为基准，拖拽中途不会被记录。
3. 几何签名变化 → 进入 **守护模式**：
   - 不在基准时：按**相对于所属显示器的偏移**还原，窗口跟着显示器走，视觉上不跳；
     并且**钳制在虚拟桌面范围内**，绝不把窗口推到所有显示器之外。
     ⚠️ 这个钳制**只能用在相对还原**上。绝对还原必须**原样使用基准矩形**——
     基准是你亲手摆的位置，天然合法。早期版本对绝对还原也钳制，结果那些
     "底边稍微挂在桌面下沿外"的窗口（例如 `811+1456=2267 > 2151`）每切一轮就被上推
     50–100px，然后被吸收成新基准，形成永久漂移。
   - 回到基准时：按**绝对坐标**还原，这一步才是真正抵消单向钳制的关键；随后 3 秒 settle 收尾。
   - **最大化状态也要恢复**：基准记的是普通矩形、窗口却是最大化，这同样算偏离基准，必须
     `SW_RESTORE` + 还原基准矩形。早期代码写成「只要当前是最大化且在正确屏幕上就跳过」，
     结果任何被最大化的窗口都永远不会被守护——**某个 Chromium 应用窗口一直"到处乱跑"就是这个原因**。
     日志里会写 `恢复最大化状态 [标题] 最大化 -> 普通`。
   - **尺寸规则（血泪教训）**：普通窗口恢复**完整矩形（位置 + 尺寸）**，这一步不能省——
     主屏从 4K 切到 1080p 时 Windows 会把超宽窗口裁窄，而且**永不归还**；只移动不恢复尺寸的话，
     每切一次窗口就被削窄一点（实测某个窗口一轮就从 3783 宽掉到 1860 宽）。
     但**最大化窗口只移动、绝不设尺寸**，它的尺寸归系统管。
   - **绝对禁止**：早期版本对「判定为最大化」的窗口做
     `ShowWindow(SW_RESTORE)` → `SetWindowPos(宽/2, 高/2)` → `ShowWindow(SW_MAXIMIZE)`，
     而且每 200ms 一次、无次数上限。这正是把某个 Chromium 应用的 GPU 合成器打坏的原因
     （`Intermediate D3D Window` 偏移 `+1140,+390`，画面整块错位，只能重启该应用的 GPU 进程救回）。该路径已彻底删除。
   - **卡住就放弃**：任一窗口连续 6 次没能在设定后停在目标位置，本次守护永久放弃它并写日志，
     从结构上杜绝反复抽打同一个窗口。
   - **基准消毒**：中心不在任何屏幕范围内的矩形一律拒绝写入基准。
4. **鼠标左键按住时不再跳过还原**（早期版本有这个检查，结果战舰世界按住左键瞄准时守护整个失效）。
5. **基准宽限期（8 秒）**：显示切换结束后，Windows 和应用常常还会继续"迟到的钳制"几秒钟。
   如果这时立刻重采基准，工具就会**把没守住的位移悄悄当成新的正确位置**，于是之后每份报告
   都显示 `OK`——它在自我欺骗。所以距上次守护结束不足 8 秒时，窗口大位移一律**不采纳**，
   保留旧基准，并在日志里写 `基准暂缓(...) 保留旧基准`。
6. **基准的任何变化都写日志**：`基准更新(距上次守护 Ns) [标题] (x,y) WxH -> (nx,ny) nWxnH`。
   超过 8px 的位移/缩放才会记录。这样"基准漂移"永远不可能再被静默吸收。
7. 每次守护结束写一份 `guardoff-HHmmss.txt` 报告：逐个窗口列出基准坐标、实时坐标、偏差，
   末尾给出 `MISMATCH = n / m`。
   ⚠️ 注意报告的含义：它证明"现在 == 基准"，**不证明基准本身是对的**。要确认基准没漂，
   必须回看 `guardian.log` 里有没有 `基准更新` / `基准暂缓`。

窗口筛选：可见、未最小化、有标题、≥60×60、非 `Progman`/`WorkerW`/任务栏/提示类、
不覆盖整块屏（全屏应用直接跳过）、排除游戏自身进程（`wgc*` / `WorldOfWarships*`）。
`WS_EX_TOOLWINDOW` 的窗口**会被跟踪**——DeskBox 的「内容格子」正是这一类。

## 建议

先点一次 **「以当前布局为基准」**，把你**现在**的窗口摆放定为基准——
那些已经被之前几次全屏搞歪了的窗口，别把歪的位置当成正确位置记下来。

## 自定义排除

在同目录建 `exclude.txt`，一行一条：

```
# 按进程名排除
p:Photoshop
# 按窗口类名排除
c:SomeWeirdClass
```

## 命令行

```
WindowGuardian.exe                  弹出控制面板（正常用法）
WindowGuardian.exe --tray           静默启动，直接进托盘（开机自启用的就是这个）
WindowGuardian.exe --dump [文件]     导出基准与实时位置，然后退出
WindowGuardian.exe --test 60        无界面跑 60 秒后自动退出（用于脚本化验证）
```

## 重新编译

**必须加 `/codepage:65001`**，否则源码里的中文字面量会被 csc 按 ANSI 读成乱码：

```
csc /nologo /target:winexe /platform:anycpu /codepage:65001 ^
    /out:WindowGuardian.exe ^
    /r:System.Windows.Forms.dll /r:System.Drawing.dll /r:System.dll ^
    WindowGuardian.cs
```

编译产物请放到普通目录再运行。若所在目录带低完整性标签，生成的 exe 会以 LOW 完整性启动。

## 注意事项

- **完整性级别必须 ≥ MEDIUM。** 程序启动时会自检：若为 LOW/Untrusted，控制面板会**整行变红**
  并写严重警告。该级别下 Windows 的 UIPI 会拒绝所有跨进程窗口操作（`SetWindowPos` 返回
  `ERROR_ACCESS_DENIED`），守护完全失效**且不会报错**。
- 无法移动**权限比它高**的窗口（例如以管理员身份运行的程序）。要覆盖这些窗口，请右键
  「以管理员身份运行」本工具。
- 只在显示拓扑变化后的窗口期内动手；平时随便拖窗口、缩放，它一句话都不说。
- 日志写在同目录 `guardian.log`，排查时先看开头那行 `完整性级别=`。
